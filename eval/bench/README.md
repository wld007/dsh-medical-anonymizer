# 匿名化架构对比评测

这套评测用一份带标注的合成病历语料，比较三种做法的效果：「规则」「单模型」，以及插件的三层架构（识别模型 + 规则替换 + 核验模型）。结果见 [docs/benchmark](../../docs/benchmark/README.md)。

语料里的人名、证件号、电话、地址和机构都是虚构的，地名也是虚构城市，例如东江市、云溪县。证件号和银行卡号只是格式和校验位正确。所以输出、报告和样例都可以原样公开。

## 运行

```bash
W=eval/bench/.tmp
node eval/bench/gen.mjs $W                                       # 生成语料与标注（固定种子）
node eval/bench/run.mjs $W rules model rules+model full-same full \
  model@2 model@3 rules+model@2 rules+model@3 full-same@2 full-same@3 full@2 full@3
node eval/bench/score.mjs $W rules model model@2 model@3 rules+model rules+model@2 rules+model@3 \
  full-same full-same@2 full-same@3 full full@2 full@3
node eval/bench/report.mjs $W docs/benchmark/index.html
```

- **模型端点**：先读环境变量 `DETECT_URL` / `DETECT_MODEL` / `VERIFY_URL` / `VERIFY_MODEL`；没有设置时，读 DSH profile 里本插件的设置（见 `models.mjs`）。
- **请求并发**：用 `BENCH_SLOTS` 设置，默认 8，所有配置相同。
- **重复运行**：配置名后加 `@标签` 表示重复运行，结果另存。报告会把同一配置的多次运行合并，取中位并标出范围。
- **对比旧版本**：设置 `BENCH_LIB=<另一份 lib 目录>`，用旧版本运行流水线，例如 `git archive v0.10.1 lib vendor package.json | tar -x -C /tmp/old`。旧版本的运行要命名为 `full@old`、`full@old2`……

| 配置 | 含义 |
|---|---|
| `rules` | 只用规则（不配模型时插件的行为） |
| `model` | 只用识别模型：原文分块交给识别模型，按返回片段全文替换；不经规则、字段画像和核验 |
| `rules+model` | 规则 + 识别模型，核验关闭，1 轮 |
| `full-same` | 三层架构，但由识别模型自己核验 |
| `full` | 三层架构：规则 + 识别模型 + 独立盲审，最多 3 轮 |

## 语料

18 位病人共 100 个文件，有以下几类：

- **文书**：入院记录、首次病程、查房、手术、会诊（Markdown）、出院小结、知情同意书、护理记录、电话随访、转院信、检验单、影像报告。
- **表格**：检验结果表、处方明细（CSV）。
- **平台导出**：字段名是数据元编码的 JSON。
- **病历条目**：条目名/条目值结构的 JSON，含病历模板标记。

`gold.json` 记录每个文件里的三类内容：

- **标识符**：每处的位置、类型和难点（`case`）。
  - 难点有 30 类，例如：叙述中的家属和医护姓名、复姓、少数民族姓名、字间空格的签名、分组书写的证件号/手机号/银行卡号、座机带分机、15 位旧证号、农村地址、工作单位、外院名称、Markdown 表格、病历模板标记、编码字段名（如 `DE02.01.039.00`）里的姓名，以及不带前缀的纯数字病历号、住院号、门诊号。
- **陷阱**：不应被替换的值，共 14 类，例如：人名命名的病名和体征（帕金森病、巴宾斯基征）、像人名的中药（徐长卿、刘寄奴）、姓氏开头的词（高血压、张力性气胸）、地名病名（克山病）、科室病区、泛指机构（上级医院）、药企和器械、批准文号、各类编码、时间戳、已遮盖的值（张*）。
- **中性值**：有争议的值，保留不算泄漏，替换也不算误改，例如：机构代码、标本条码、处方号、只写到县的出生地。

生成器会自动检查标注：标识符原文在文件里每次出现都必须有标注，否则替换它会被误记为误改。

## 计分

原文与输出逐行做字符级对齐。

- **泄漏**：一处标识符有超过一半的字符原样保留。
- **误改**：标识符和中性值以外被改动的字符，按连续片段计数。
- **陷阱丢失**：输出中某个陷阱的出现次数少于原文。
- **JSON 损坏**：输出不再能解析为 JSON。

## 局限

- 语料由模板生成，比真实病历规整。
- 病人跨文件重复出现，这对流水线的批内扩散有利。
- 语料中没有 OCR 错字和超大表格。
- 温度设为 0，但服务端批处理仍会带来波动，所以每个配置都应跑 3 次。

因此，结果能说明各层的作用和短板，但不能直接当作真实数据上的泄漏率。
