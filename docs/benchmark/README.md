# 匿名化架构对比评测（合成病历）

可视化报告：[index.html](index.html)。下载后用浏览器打开即可，不需要联网。

这次评测在同一份合成病历上，比较「只用规则」「只用模型」和插件的三层架构（识别模型 + 规则替换 + 核验模型）。语料、计分方法和复现步骤见 [eval/bench/README.md](../../eval/bench/README.md)。

- **测试环境**：插件 0.11.1；识别模型 qwen3.6-35b-a3b，核验模型 gemma-4-26b-a4b-it，都部署在本地，温度为 0。
- **语料**：100 个文件，含 1452 处标识符、924 个陷阱。标识符的难点有 31 类，陷阱有 14 类。所有内容都是虚构的。
- **运行次数**：用到模型的配置各跑 3 次，下表给出中位数和范围。

## 结果

| 配置 | 泄漏（3 次） | 召回 | 全清文件 | 误改片段 | 陷阱丢失 | tokens |
|---|---|---|---|---|---|---|
| 仅规则 | 216 | 85.1% | 20 / 100 | 0 | 0 | 0 |
| 仅模型 | 226（224–229） | 84.4% | 63 / 100 | 8（6–9） | 7（5–8） | 89k |
| 规则 + 识别模型（无核验） | 91（79–107） | 93.7% | 76 / 100 | 0（0–1） | 0 | 61k |
| 三层，识别模型自己核验 | 19（16–22） | 98.7% | 86 / 100 | 0 | 0 | 139k |
| 三层，本轮修复前（b632594） | 24（24–26） | 98.3% | 81 / 100 | 46 | 12 | 145k |
| **三层（当前）** | **19（18–19）** | **98.7%** | **86 / 100** | **0** | **0** | 152k |

## 结论

1. **规则和模型各漏一类，互不重合。**
   - 只用规则：漏的是没有标签可依的内容，比如叙述中的姓名和地址、农村地址、字间带空格的签名，以及大量签名和医护姓名。
   - 只用模型：漏的是格式固定、本该很容易的东西，比如编码字段里的纯数字病历号/门诊号（58/60）、外院名称、工作单位、表格列；还会把已经遮盖的值（如“张*”）再替换一遍。
   - 两者单独用，泄漏都在 220 处左右；叠加后降到约 90 处。
2. **核验层把泄漏再减少约八成（约 90 → 19），并且让结果更稳定。** 不加核验时，3 次运行的泄漏在 79–107 之间；加了核验后在 18–19 之间。用独立的核验模型和让识别模型自己核验，在这份语料上差别不大（19 对 19），但独立核验的波动更小。
3. **本轮修复消除了全部误改和陷阱丢失**（46 段 → 0；12 个 → 0），并修好了分组书写的身份证号（6 处泄漏 → 0）。被误改的包括：吞并了前文的医院名、“生于原籍”、“建议/经上级医院”。
4. **当前还漏的**：
   - 叙述中的外院医护姓名，例如“已与某医院的某某医生电话沟通”“邀请某某教授会诊”；
   - 编码字段里的纯数字病历号/门诊号，有少量漏掉；
   - 个别少数民族姓名。

   第一类是下一步最值得改进的地方，后两类可以用内置数据元编码字典来补。

## 局限

- 语料由模板生成，比真实病历规整。
- 病人跨文件重复出现，这对流水线的批内扩散有利。
- 语料中没有 OCR 错字和超大表格。

因此，这些结果能说明各层的作用和短板，但不能直接当作真实数据上的泄漏率。
